2.1 Gestión de imágenes

Una imagen Docker es una plantilla de solo lectura compuesta de capas superpuestas (Union File System). Cada instrucción del Dockerfile crea una nueva capa. Las capas se reutilizan entre imágenes, ahorrando espacio y acelerando las descargas.
Comandos de gestión de imágenes
# Descargar imagen del registro
docker pull nginx:1.25
docker pull php:8.2-fpm
docker pull mysql:8.0

# Listar imágenes locales
docker images
docker image ls
docker image ls --format '{{.Repository}}:{{.Tag}} → {{.Size}}'

# Inspeccionar imagen (capas, configuración, metadatos)
docker inspect nginx:1.25
docker image history nginx:1.25   # ver capas y su tamaño

# Etiquetar imagen
docker tag mi-app:latest miusuario/mi-app:1.0

# Eliminar imagen
docker rmi nginx:1.25
docker image rm php:8.1

# Limpiar imágenes sin usar (dangling)
docker image prune
docker image prune -a   # también las no referenciadas

# Buscar en Docker Hub
docker search php --limit 10

# Guardar imagen a archivo tar
docker save -o nginx.tar nginx:1.25

# Cargar imagen desde tar
docker load -i nginx.tar

2.2 Instrucciones del Dockerfile

InstrucciónDescripción
FROMImagen base. SIEMPRE es la primera instrucción. FROM ubuntu:22.04
RUNEjecuta comandos en tiempo de BUILD (instalar paquetes, etc.)
CMDComando por defecto al EJECUTAR el contenedor. Se puede sobreescribir.
ENTRYPOINTComando principal del contenedor. No se sobreescribe fácilmente.
COPYCopia archivos del host al contenedor. COPY src dst
ADDComo COPY pero puede descomprimir .tar y descargar URLs. Preferir COPY.
WORKDIREstablece el directorio de trabajo para instrucciones siguientes.
ENVDefine variables de entorno disponibles en build y runtime.
ARGDefine variables solo disponibles durante el build.
EXPOSEDocumenta el puerto que usa el contenedor (no lo publica).
VOLUMECrea un punto de montaje para persistencia de datos.
USERCambia el usuario con el que se ejecutan las siguientes instrucciones.
LABELMetadatos de la imagen: autor, versión, descripción...
HEALTHCHECKDefine cómo comprobar si el contenedor está sano.
ONBUILDInstrucción que se activa cuando la imagen se usa como base de otra.

2.3 Dockerfile completo para PHP con Apache

Dockerfile
# ── Imagen base oficial de PHP con Apache ───────────────────
FROM php:8.2-apache

# ── Metadatos ───────────────────────────────────────────────
LABEL maintainer="alumno@daw.es"
LABEL version="1.0"
LABEL description="App PHP con Apache para 2DAW"

# ── Variables de entorno ─────────────────────────────────────
ENV APACHE_DOCUMENT_ROOT=/var/www/html
ENV PHP_MEMORY_LIMIT=256M
ENV TZ=Europe/Madrid

# ── Instalar extensiones PHP y herramientas ──────────────────
# Combinar RUN en una sola capa para minimizar tamaño
RUN apt-get update && apt-get install -y \
    libpng-dev \
    libonig-dev \
    libxml2-dev \
    zip unzip curl \
    && docker-php-ext-install \
    pdo pdo_mysql mbstring exif pcntl bcmath gd \
    && a2enmod rewrite \
    && apt-get autoremove -y \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*

# ── Instalar Composer ────────────────────────────────────────
COPY --from=composer:2 /usr/bin/composer /usr/bin/composer

# ── Configuración personalizada de Apache ───────────────────
COPY docker/apache/000-default.conf /etc/apache2/sites-available/000-default.conf

# ── Directorio de trabajo ────────────────────────────────────
WORKDIR /var/www/html

# ── Copiar archivos de dependencias primero (caché de capas) ─
COPY composer.json composer.lock ./
RUN composer install --no-dev --optimize-autoloader --no-interaction

# ── Copiar el resto del código ───────────────────────────────
COPY . .

# ── Permisos correctos ───────────────────────────────────────
RUN chown -R www-data:www-data /var/www/html \
    && chmod -R 755 /var/www/html/storage

# ── Usuario no-root por seguridad ────────────────────────────
USER www-data

# ── Puerto que expone el contenedor ─────────────────────────
EXPOSE 80

# ── Healthcheck ──────────────────────────────────────────────
HEALTHCHECK --interval=30s --timeout=10s --start-period=60s --retries=3 \
    CMD curl -f http://localhost/ || exit 1

2.4 docker build — Opciones

docker build
# Sintaxis: docker build [opciones] CONTEXTO
# El contexto es el directorio que se envía al daemon (normalmente .)

# Build básico (busca Dockerfile en el directorio actual)
docker build -t mi-app:1.0 .

# Especificar Dockerfile alternativo
docker build -f docker/Dockerfile.prod -t mi-app:prod .

# Pasar argumentos de build (ARG en el Dockerfile)
docker build --build-arg NODE_ENV=production -t mi-app .

# Build sin caché (fuerza reconstrucción completa)
docker build --no-cache -t mi-app .

# Múltiples etiquetas
docker build -t mi-app:1.0 -t mi-app:latest .

# Ver progreso detallado
docker build --progress=plain -t mi-app .

# Build para múltiples plataformas (buildx)
docker buildx build --platform linux/amd64,linux/arm64 -t mi-app:multi .

# .dockerignore — archivos a excluir del contexto de build
# node_modules/
# .git/
# .env
# *.log
# tests/
# README.md
.dockerignore es importante para el examen. Excluir node_modules, .git, .env, logs → reduce el contexto enviado al daemon → builds más rápidos. Formato idéntico a .gitignore. NUNCA incluir credenciales reales en la imagen.
