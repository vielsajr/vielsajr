11.1 Docker Swarm

Node (nodo): Servidor en el clúster. Puede ser Manager o Worker.

Manager Node: Mantiene el estado del clúster. El primero también actúa como Worker.

Worker Node: Ejecuta los contenedores asignados por el Manager.

Service: Definición de cómo ejecutar una imagen (equivalente a docker run pero distribuido).

Task: Unidad de trabajo: un contenedor ejecutando en un nodo específico.

Stack: Conjunto de servicios definidos en docker-compose.yml para Swarm.

Overlay Network: Red virtual que conecta contenedores en diferentes hosts del clúster.

Replica: Número de instancias del mismo servicio. Swarm las distribuye en los nodos.
Swarm — Comandos esenciales
# ── Inicializar el clúster (en el Manager) ───────────────────
docker swarm init
docker swarm init --advertise-addr 192.168.1.10

# Obtener token para unir workers
docker swarm join-token worker
docker swarm join-token manager

# ── En el nodo Worker (copiar comando del token) ──────────────
docker swarm join --token SWMTKN-1-xxx... 192.168.1.10:2377

# ── Gestión de nodos ──────────────────────────────────────────
docker node ls
docker node inspect mi-nodo
docker node update --availability drain mi-nodo   # drenar nodo
docker node rm mi-nodo

# ── Servicios (equivalente a docker run en Swarm) ─────────────
docker service create \
  --name web \
  --replicas 3 \
  --publish published=80,target=80 \
  --network mi-overlay \
  nginx:1.25

docker service ls
docker service ps web                # ver dónde se ejecutan las tareas
docker service inspect web
docker service logs -f web

# Escalar servicio
docker service scale web=5
docker service update --replicas 5 web

# Actualizar imagen (rolling update)
docker service update --image nginx:1.26 web
docker service update --image nginx:1.26 --update-parallelism 2 --update-delay 10s web

# Rollback
docker service rollback web

# Eliminar servicio
docker service rm web

# ── Stacks (docker compose para Swarm) ───────────────────────
docker stack deploy -c docker-compose.yml mi-stack
docker stack ls
docker stack services mi-stack
docker stack ps mi-stack
docker stack rm mi-stack

# ── Salir del clúster ────────────────────────────────────────
docker swarm leave
docker swarm leave --force            # en el Manager

11.2 Nociones de Kubernetes (K8s)

Pod: Unidad mínima. Uno o varios contenedores que comparten red y almacenamiento.

Node: Servidor (VM o físico) del clúster. Ejecuta los Pods.

Cluster: Conjunto de Nodes gestionados por Kubernetes.

Control Plane: Nodo(s) que gestionan el clúster (API Server, Scheduler, etcd...).

Deployment: Gestiona el ciclo de vida de Pods: réplicas, rolling updates, rollbacks.

Service: Abstracción de red para exponer Pods (ClusterIP, NodePort, LoadBalancer).

Namespace: Aislamiento lógico dentro del clúster (ej: desarrollo, producción).

ConfigMap / Secret: Configuración no sensible / datos sensibles cifrados.

Ingress: Enrutamiento HTTP/HTTPS hacia los Services del clúster.

kubectl: CLI para interactuar con el clúster Kubernetes.
kubectl — Comandos básicos
# Obtener info del clúster
kubectl cluster-info
kubectl get nodes

# Pods
kubectl get pods
kubectl get pods -n mi-namespace
kubectl describe pod mi-pod
kubectl logs -f mi-pod
kubectl exec -it mi-pod -- bash

# Deployments
kubectl get deployments
kubectl apply -f deployment.yaml
kubectl scale deployment mi-app --replicas=3
kubectl rollout status deployment/mi-app
kubectl rollout undo deployment/mi-app

# Services
kubectl get services
kubectl expose deployment mi-app --port=80 --type=LoadBalancer

# Borrar recursos
kubectl delete pod mi-pod
kubectl delete -f deployment.yaml
deployment.yaml — Ejemplo básico K8s
apiVersion: apps/v1
kind: Deployment
metadata:
  name: mi-app
  labels:
    app: mi-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: mi-app
  template:
    metadata:
      labels:
        app: mi-app
    spec:
      containers:
        - name: mi-app
          image: miusuario/mi-app:1.0
          ports:
            - containerPort: 80
          env:
            - name: DB_HOST
              value: 'mysql-service'
          resources:
            limits:
              memory: '512Mi'
              cpu: '500m'
            requests:
              memory: '256Mi'
              cpu: '250m'
---
apiVersion: v1
kind: Service
metadata:
  name: mi-app-service
spec:
  selector:
    app: mi-app
  ports:
    - port: 80
      targetPort: 80
  type: LoadBalancer
