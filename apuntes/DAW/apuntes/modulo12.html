12.1 Concepto de CI/CD

CI (Continuous Integration): Integrar cambios de código frecuentemente + ejecutar tests automáticos.
CD (Continuous Delivery): Tener el código siempre listo para desplegar en producción.
CD (Continuous Deployment): Desplegar automáticamente a producción si los tests pasan.
Pipeline: Secuencia de pasos automatizados: build → test → push imagen → deploy.
Docker encaja perfectamente: cada pipeline crea una imagen inmutable y la despliega.

12.2 GitHub Actions CI/CD

.github/workflows/docker.yml
name: CI/CD Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

env:
  REGISTRY: docker.io
  IMAGE_NAME: miusuario/mi-app

jobs:
  # ── Job 1: Tests ───────────────────────────────────────────
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run tests with Docker
        run: |
          docker compose -f docker-compose.test.yml up --build --abort-on-container-exit
          docker compose -f docker-compose.test.yml down

  # ── Job 2: Build y Push imagen ────────────────────────────
  build-and-push:
    runs-on: ubuntu-latest
    needs: test
    if: github.ref == 'refs/heads/main'
    steps:
      - uses: actions/checkout@v4
      - name: Log in to Docker Hub
        uses: docker/login-action@v3
        with:
          username: ${{ secrets.DOCKERHUB_USERNAME }}
          password: ${{ secrets.DOCKERHUB_TOKEN }}
      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.IMAGE_NAME }}
          tags: |
            type=sha,prefix=sha-
            type=raw,value=latest
      - name: Build and push Docker image
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          cache-from: type=gha
          cache-to: type=gha,mode=max

  # ── Job 3: Deploy a producción ────────────────────────────
  deploy:
    runs-on: ubuntu-latest
    needs: build-and-push
    steps:
      - name: Deploy to server via SSH
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USER }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /opt/mi-app
            docker compose pull
            docker compose up -d --no-deps
            docker image prune -f

12.3 Flujo de trabajo en equipo

Flujo desarrollo → producción
# ══ DESARROLLO LOCAL ══════════════════════════════════════════
git clone https://github.com/equipo/proyecto.git
cd proyecto
cp .env.example .env
docker compose up -d
# → http://localhost:8000 listo
# El código se refleja al instante por bind mount

# ══ COMMIT Y PUSH ══════════════════════════════════════════════
git add . && git commit -m 'feat: nueva funcionalidad'
git push origin develop
# → GitHub Actions ejecuta tests automáticamente

# ══ MERGE A MAIN (tras code review) ═══════════════════════════
# → GitHub Actions: tests → build imagen → push Docker Hub → deploy

# ══ EN SERVIDOR DE PRODUCCIÓN ═════════════════════════════════
# (automatizado por CI/CD, pero manualmente sería:)
ssh usuario@servidor
cd /opt/mi-app
docker compose pull               # descargar nueva imagen
docker compose up -d              # actualizar contenedores
docker image prune -f             # limpiar imágenes antiguas
