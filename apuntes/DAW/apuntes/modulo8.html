8.1 Multi-Stage Builds

Los Multi-Stage Builds permiten usar múltiples FROM en un mismo Dockerfile. Se separa el entorno de compilación del entorno de producción, obteniendo imágenes finales mucho más pequeñas y seguras.
Dockerfile multi-stage — Node.js
# ══ STAGE 1: Dependencias y build ═══════════════════════════
FROM node:20-alpine AS builder

WORKDIR /app

# Copiar solo package.json primero (optimización de caché)
COPY package*.json ./
RUN npm ci --only=production
COPY . .
RUN npm run build

# ══ STAGE 2: Imagen de producción ════════════════════════════
FROM node:20-alpine AS production

LABEL maintainer="daw@escuela.es"

# Usuario no-root
RUN addgroup -g 1001 -S nodejs && adduser -S nextjs -u 1001

WORKDIR /app

# Copiar solo lo necesario del stage anterior
COPY --from=builder --chown=nextjs:nodejs /app/.next ./.next
COPY --from=builder /app/node_modules ./node_modules
COPY --from=builder /app/package.json ./package.json
COPY --from=builder /app/public ./public

USER nextjs

EXPOSE 3000
ENV NODE_ENV=production

HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
    CMD wget -qO- http://localhost:3000/api/health || exit 1

CMD ['node_modules/.bin/next', 'start']
Dockerfile multi-stage — PHP Laravel
# ══ STAGE 1: Base común ══════════════════════════════════════
FROM php:8.2-fpm-alpine AS base

RUN apk add --no-cache \
    libpng-dev oniguruma-dev libxml2-dev \
    && docker-php-ext-install pdo_mysql mbstring gd bcmath

COPY --from=composer:2 /usr/bin/composer /usr/bin/composer
WORKDIR /var/www/html

# ══ STAGE 2: Dependencias ════════════════════════════════════
FROM base AS deps

COPY composer.json composer.lock ./
RUN composer install --no-scripts --no-autoloader

# ══ STAGE 3: Desarrollo ══════════════════════════════════════
FROM deps AS development

COPY . .
RUN composer install --optimize-autoloader
# En dev: montamos el código con bind mount

# ══ STAGE 4: Producción ══════════════════════════════════════
FROM deps AS production

COPY . .
RUN composer install --no-dev --optimize-autoloader \
    && php artisan config:cache \
    && php artisan route:cache \
    && php artisan view:cache \
    && chown -R www-data:www-data /var/www/html

USER www-data
EXPOSE 9000
Usar stages específicos
# Build del stage de desarrollo
docker build --target development -t mi-app:dev .

# Build del stage de producción
docker build --target production -t mi-app:prod .

# En docker-compose.yml:
services:
  app:
    build:
      context: .
      target: development    # o production

8.2 Buenas prácticas en Dockerfile

✅ Buenas prácticas para imágenes Docker (importante en examen):
  • Usar imágenes base oficiales y mínimas (alpine cuando sea posible → mucho más pequeñas)
  • Combinar múltiples RUN en uno solo con && para minimizar capas
  • Limpiar caché del gestor de paquetes en el mismo RUN: && apt-get clean && rm -rf /var/lib/apt/lists/*
  • Copiar primero los archivos de dependencias (package.json, composer.json) → optimiza caché de capas
  • Usar .dockerignore para excluir archivos innecesarios del contexto
  • No ejecutar como root: crear usuario específico y usar USER
  • Usar COPY en lugar de ADD (salvo que necesites descomprimir o descargar)
  • Especificar versiones exactas en FROM: php:8.2.10-fpm-alpine3.18 (no :latest en producción)
  • Un servicio por contenedor (SRP — Single Responsibility Principle)
  • Usar HEALTHCHECK para monitoreo de salud del contenedor
  • Multi-stage builds para reducir tamaño de imagen de producción
  • No guardar secretos ni contraseñas en el Dockerfile ni en la imagen
Optimización de caché de capas
# ❌ MAL — invalida caché en cada cambio de código
FROM php:8.2-apache
COPY . /var/www/html
RUN composer install

# ✅ BIEN — composer install solo se re-ejecuta si cambia composer.json
FROM php:8.2-apache
WORKDIR /var/www/html
COPY composer.json composer.lock ./     # copiar solo manifiestos
RUN composer install --no-scripts       # capa cacheada si no cambian
COPY . .                                # copiar código (invalida solo desde aquí)
RUN composer dump-autoload --optimize
