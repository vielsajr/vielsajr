8.1 CORS — Qué es y cómo funciona

Política del mismo origen (Same-Origin Policy):
Un origen es: protocolo + dominio + puerto. Ejemplo: http://ejemplo.com:80

❌ BLOQUEADO: http://mi-web.com → https://api.otrositio.com (distinto dominio)
❌ BLOQUEADO: http://mi-web.com → http://api.mi-web.com (distinto subdominio)
❌ BLOQUEADO: http://mi-web.com:3000 → http://mi-web.com:8000 (distinto puerto)
✅ PERMITIDO: http://mi-web.com:3000 → http://mi-web.com:3000 (mismo origen)

NOTA: CORS solo aplica en el NAVEGADOR. Desde Node.js, Postman, curl no hay CORS.
cors_explicacion.js
// ── Cómo funciona CORS ───────────────────────────────────────────────
//
// 1. SIMPLE REQUEST (GET, POST con Content-Type simple):
//    Navegador → petición con cabecera 'Origin: http://mi-web.com'
//    Servidor  → respuesta con 'Access-Control-Allow-Origin: *'
//    Navegador → si la cabecera está presente: permite la respuesta
//
// 2. PREFLIGHT REQUEST (antes de POST/PUT/DELETE con JSON):
//    Navegador → petición OPTIONS a la misma URL
//    Servidor  → responde con las cabeceras CORS permitidas
//    Navegador → si OK, hace la petición real

// ── Cabeceras CORS del SERVIDOR (configurar en PHP/Node/etc.) ────────
// Access-Control-Allow-Origin: *
// Access-Control-Allow-Origin: https://mi-web.com
// Access-Control-Allow-Methods: GET, POST, PUT, PATCH, DELETE, OPTIONS
// Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With
// Access-Control-Allow-Credentials: true  (para cookies/auth)
// Access-Control-Max-Age: 86400           (cachear preflight por 24h)

// ── Configurar CORS en PHP ────────────────────────────────────────────
// header('Access-Control-Allow-Origin: *');
// header('Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS');
// header('Access-Control-Allow-Headers: Content-Type, Authorization');
// if ($_SERVER['REQUEST_METHOD'] === 'OPTIONS') { exit(0); }

// ── Configurar CORS en Laravel ────────────────────────────────────────
// En config/cors.php:
// 'allowed_origins' => ['https://mi-frontend.com'],
// 'allowed_methods' => ['*'],
// 'allowed_headers' => ['*'],

8.2 Cabeceras de petición importantes

CabeceraDescripción
Content-TypeTipo de datos del body enviado. application/json para JSON, multipart/form-data para archivos.
AcceptQué tipo de datos acepta el cliente. Accept: application/json
AuthorizationCredenciales de autenticación. Authorization: Bearer token123
X-Requested-WithIdentificar petición AJAX. X-Requested-With: XMLHttpRequest
OriginOrigen de la petición (lo pone el navegador automáticamente en CORS).
CookieCookies enviadas al servidor (solo si credentials: include).
Cache-ControlControlar el caché. Cache-Control: no-cache
If-Modified-SinceCaché condicional: solo enviar si fue modificado desde esta fecha.
