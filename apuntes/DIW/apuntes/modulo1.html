1.1 ¿Qué es AJAX?

AJAX (Asynchronous JavaScript And XML) permite enviar y recibir datos del servidor en segundo plano, sin recargar la página. Hoy en día se usa JSON (no XML) y Fetch API (no XHR). Sin AJAX: el navegador carga la página ENTERA al hacer clic. Con AJAX: JavaScript pide datos en segundo plano y solo actualiza la parte necesaria del DOM. Ejemplos: búsqueda Google, Instagram scroll infinito, Gmail.

1.3 Síncrono vs Asíncrono

asincronia.js
// ── PROBLEMA: código SÍNCRONO (bloquea todo) ──────────────────────────
// Esto NO existe en AJAX moderno, pero ilustra el problema:
// const datos = esperarRespuestaServidor(); // ← bloquea 3 segundos
// console.log('Esto no se ejecuta hasta que lleguen los datos');

// ── SOLUCIÓN 1: Callbacks (forma antigua) ─────────────────────────────
function obtenerUsuario(id, callback) {
  const xhr = new XMLHttpRequest();
  xhr.open('GET', `/api/usuarios/${id}`);
  xhr.onload = function() {
    if (xhr.status === 200) {
      callback(null, JSON.parse(xhr.responseText)); // éxito
    } else {
      callback(new Error('Error: ' + xhr.status));  // error
    }
  };
  xhr.onerror = () => callback(new Error('Error de red'));
  xhr.send();
}

// Uso con callback — 'Callback Hell' si se anidan
obtenerUsuario(1, function(error, usuario) {
  if (error) { console.error(error); return; }
  console.log(usuario.nombre); // aquí ya tenemos los datos
});

console.log('Esto se ejecuta ANTES que el console.log de arriba');

1.4 El Event Loop de JavaScript

Call Stack: donde se ejecuta el código sincrónico. Solo puede hacer una cosa a la vez.

Web APIs: el navegador gestiona las operaciones lentas (peticiones HTTP, timers, eventos) fuera del stack.

Callback Queue: cuando la Web API termina, pone el callback en la cola.

Event Loop: continuamente comprueba si el Call Stack está vacío; si lo está, mueve callbacks de la cola al stack.

Microtask Queue: cola especial de mayor prioridad para Promises. Se vacía ANTES que la Callback Queue.

Implicación práctica: .then() de una Promise siempre se ejecuta DESPUÉS del código síncrono actual.
eventloop_demo.js
// Demo del Event Loop — predecir el orden de ejecución
console.log('1 — síncrono');

setTimeout(() => {
  console.log('4 — setTimeout (Callback Queue)');
}, 0); // ← aunque sea 0ms, va a la cola y espera

Promise.resolve()
  .then(() => console.log('3 — Promise (Microtask Queue)'));

console.log('2 — síncrono');

// Salida:
// 1 — síncrono
// 2 — síncrono
// 3 — Promise (Microtask Queue)  ← las microtasks van primero
// 4 — setTimeout (Callback Queue)
