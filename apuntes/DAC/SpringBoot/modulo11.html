11.1 Arquitectura del proyecto

Capas de la aplicación:

Controller Layer — Recibe peticiones HTTP, delega al servicio, devuelve respuesta. Sin lógica de negocio.

Service Layer — Lógica de negocio, validaciones, transacciones, coordinación entre repositorios.

Repository Layer — Acceso a datos. Solo consultas/operaciones de BD. Usa JPA/Spring Data.

Model/Entity — Representación de tablas de la BD. Solo datos, sin lógica.

DTO Layer — Objetos para transferir datos entre capas y hacia el cliente. Separan el modelo de la API.

Regla de oro: Controller usa Service. Service usa Repository. NUNCA el Repository usa el Service.

11.2 Patrón DTO y Mapper

ProductoDTO.java / ProductoMapper.java 
// ── DTO pattern (separar entidad de respuesta API) ────────────

// Entidad (BD):
@Entity
public class Producto {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY) Long id;
    String nombre;
    BigDecimal precio;
    Integer stock;
    @ManyToOne Categoria categoria;
    String password;  // ← campo sensible, NO debe ir en la respuesta
}

// DTO de respuesta (lo que ve el cliente):
public record ProductoDTO(Long id, String nombre, BigDecimal precio, String categoriaNombre) {}

// DTO de petición (lo que envía el cliente):
public record ProductoRequest(
    @NotBlank String nombre,
    @Positive BigDecimal precio,
    @PositiveOrZero Integer stock,
    @NotNull Long categoriaId
) {}

// Mapper manual (o usa MapStruct para generar automáticamente):
@Component
public class ProductoMapper {
    public ProductoDTO toDTO(Producto p) {
        return new ProductoDTO(p.getId(), p.getNombre(), p.getPrecio(),
            p.getCategoria() != null ? p.getCategoria().getNombre() : null);
    }
}
