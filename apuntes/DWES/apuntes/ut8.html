Unidad Temática 8

Servicios Web REST

Introducción a servicios web, SOAP vs REST, clientes cURL y Http facade, creación de APIs en Laravel con Resources, inserción, actualización y autenticación con Sanctum.

01 Introducción

Las aplicaciones a veces necesitan compartir información con otras aplicaciones. Una primera idea es dar acceso directo a la base de datos, pero esto no es una buena idea:

  • Cuantas más aplicaciones usen los mismos datos, más posibilidades de generar errores.
  • La lógica de negocio ya programada no se podrá aprovechar en otras aplicaciones.
  • Al dar acceso directo a los datos, será complicado mantener el control sobre las modificaciones.

02 Servicios Web

Un servicio web es un método que permite que dos equipos intercambien información a través de una red informática. El servidor ofrece un punto de acceso controlado a la información. Los clientes no necesitan conocer la estructura interna de almacenamiento.

Mecanismos y protocolos

Los servicios web utilizan el protocolo HTTP, lo que les permite funcionar sobre cualquier servidor web usando el puerto 80. La respuesta obtenida no es una página web, sino la información solicitada en un formato estructurado.

SOAP vs REST

CaracterísticaSOAPREST
FormatoXML (estructurado)JSON, XML, binario, text…
ProtocoloHTTP, SMTP, etc.HTTP (GET, POST, PUT, DELETE, PATCH)
ComplejidadEstructura compleja, reglas y estándares estrictosLiviano y flexible
RendimientoMayor sobrecarga de ancho de bandaMás rápido en procesamiento
InteroperabilidadAlta entre sistemas heterogéneosAlta, muy extendido

La gran mayoría de servicios REST transmite en JSON porque es interpretado de forma natural por JavaScript.

03 Servicios web REST

REST es mucho más flexible que SOAP. Permite usar los métodos HTTP: GET, POST, PUT, DELETE, PATCH. El tipo de datos está definido por el Header Content-Type.

Cliente clásico — cURL

La librería cURL permite conectarse y comunicarse con diferentes tipos de servidores:

$url_servicio = "http://museo.laravel/api";
$curl = curl_init($url_servicio);
curl_setopt($curl, CURLOPT_CUSTOMREQUEST, "GET");
curl_setopt($curl, CURLOPT_RETURNTRANSFER, true);
$respuesta_curl = curl_exec($curl);
curl_close($curl);

$respuesta_decodificada = json_decode($respuesta_curl);

Cliente moderno — Http facade (Laravel)

Laravel incluye un cliente HTTP moderno basado en Guzzle mediante la fachada Http:

use Illuminate\Support\Facades\Http;

public function obtenerDatos()
{
    $respuesta = Http::get('https://URL_API');

    if ($respuesta->failed()) {
        return response()->json(['error' => 'Servicio no disponible'], 503);
    }

    return $respuesta->json();
}

// Con token de autenticación
$respuesta = Http::withToken($token)
    ->get('https://api.misitio.com/api/articulos');

// Con cabecera Authorization manual
$respuesta = Http::withHeaders([
    'Authorization' => 'Bearer ' . $token
])->get('https://api.misitio.com/api/articulos');

04 Crear servicios web en Laravel

Rutas de la API

Desde Laravel 11, ejecutar el siguiente comando para generar el fichero de rutas de la API:

php artisan install:api

Crea el fichero routes/api.php. Usar Route::apiResource() para generar rutas RESTful automáticamente:

// routes/api.php
Route::apiResource('articulos', ArticuloApiController::class);

Genera las rutas CRUD estándar con los métodos index, store, show, update y destroy:

GET|HEAD    api/articulos                 articulos.index
POST        api/articulos                 articulos.store
GET|HEAD    api/articulos/{articulo}      articulos.show
PUT|PATCH   api/articulos/{articulo}      articulos.update
DELETE      api/articulos/{articulo}      articulos.destroy

Controlador de API

php artisan make:controller ArticuloApiController --api

Crea los métodos index, store, show, update y destroy predefinidos.

Resources

Los Resources dan forma a las respuestas JSON de la API. Permiten personalizar la presentación y mantener consistencia.

# Resource para un único modelo
php artisan make:resource ArticuloResource

# Resource Collection para colecciones
php artisan make:resource ArticuloCollection

Resource → transforma un solo modelo en respuesta JSON.

Resource Collection → transforma colecciones de modelos en respuestas JSON estructuradas.

El método toArray($request) define la transformación:

// App/Http/Resources/ArticuloResource.php
public function toArray($request)
{
    return [
        'id'                => $this->id,
        'titulo'            => $this->titulo,
        'contenido'         => $this->contenido,
        'fecha_publicacion' => $this->created_at->format('Y-m-d'),
    ];
}

Uso en controladores:

// Obtener un artículo (show)
public function show(Articulo $articulo)
{
    return new ArticuloResource($articulo);
}

// Obtener colección (index)
public function index()
{
    $articulos = Articulo::all();
    return new ArticuloCollection($articulos);
}

// Con paginación
public function index()
{
    $articulos = Articulo::paginate(5);
    return new ArticuloCollection($articulos);
}

05 Insertar datos

La inserción usa el método POST. La ruta ya está generada con Route::apiResource.

Método store en el controlador

class ArticuloApiController extends Controller
{
    public function store(Request $request)
    {
        $request->validate([
            'titulo'    => 'required|string|max:255',
            'contenido' => 'required|string',
        ]);

        return new ArticuloResource(Articulo::create($request->all()));
    }
}

Form Request personalizado para la API

php artisan make:request CreateArticuloRequest

Se crea en app/Http/Requests/CreateArticuloRequest.php:

class CreateArticuloRequest extends FormRequest
{
    public function authorize() { return true; }

    public function rules()
    {
        return [
            'titulo'    => 'required|string|max:255',
            'contenido' => 'required|string',
        ];
    }
}

En el controlador, usar CreateArticuloRequest en lugar de Request. Si la validación falla, Laravel enviará automáticamente una respuesta JSON con los errores:

public function store(CreateArticuloRequest $request)
{
    // Los datos ya han sido validados
    return new ArticuloResource(Articulo::create($request->all()));
}

Probar con Postman

  • Tipo de solicitud: POST
  • Pestaña Body → seleccionar raw con formato JSON
  • Enviar y analizar la respuesta

06 Actualizar datos

Se usa la ruta PUT (o PATCH) generada por apiResource. El método del controlador es update.

php artisan make:request UpdateArticuloRequest
class ArticuloApiController extends Controller
{
    public function update(UpdateArticuloRequest $request, Articulo $articulo)
    {
        $articulo->update($request->all());
        return new ArticuloResource($articulo);
    }
}

PUT vs PATCH

MétodoComportamiento
PUTEl cliente debe proporcionar la representación completa del recurso. Los campos no enviados se consideran nulos.
PATCHPermite actualizar solo los campos específicos sin afectar los demás. Útil para actualizaciones parciales.

Validación que distingue PUT de PATCH usando la regla sometimes:

class UpdateArticuloRequest extends FormRequest
{
    public function authorize() { return true; }

    public function rules()
    {
        $metodo = $this->method();
        if ($metodo == 'PUT') {
            return [
                'titulo'    => 'required|string|max:255',
                'contenido' => 'required|string',
            ];
        } else {
            // PATCH: solo valida si el campo está presente
            return [
                'titulo'    => 'sometimes|string|max:255',
                'contenido' => 'sometimes|string',
            ];
        }
    }
}

La regla sometimes indica que la validación solo se aplica si el campo está presente en la solicitud.

07 Autenticación con Sanctum

Para proteger las rutas se usa Sanctum (incluido en Laravel por defecto en composer.json). Usa un sistema de tokens en lugar de sesiones, adecuado para APIs.

Generación de tokens

Añadir el trait HasApiTokens al modelo User:

use Laravel\Sanctum\HasApiTokens;

class User extends Authenticatable
{
    use HasApiTokens;
}

Crear ruta en routes/web.php para generar tokens:

Route::get('/profile/crearToken', [ProfileController::class, 'crearToken'])
    ->name('profile.crearToken')->middleware('auth');

Método en el controlador:

public function crearToken(Request $request)
{
    $request->user()->tokens()->delete(); // Borrar tokens anteriores
    $token = $request->user()->createToken('token-api');
    return ['token' => $token->plainTextToken];
}

Proteger rutas de la API

// routes/api.php
Route::middleware("auth:sanctum")->group(function () {
    Route::apiResource('articulos', ArticuloApiController::class);
});

Revocación de tokens

// Revocar todos los tokens del usuario
$user->tokens()->delete();

// Revocar el token actual de la petición
$request->user()->currentAccessToken()->delete();

// Revocar un token específico
$user->tokens()->where('id', $tokenId)->delete();

Habilidades (Abilities) de tokens

Sanctum permite asignar habilidades a los tokens para control de acceso granular:

// Crear token con habilidades
$token = Auth::user()->createToken('token-api', ['crear-articulo']);

// Comprobar habilidad
if ($user->tokenCan('crear-articulo')) {
    // ...
}

Añadir middleware de habilidades en bootstrap/app.php:

use Laravel\Sanctum\Http\Middleware\CheckAbilities;
use Laravel\Sanctum\Http\Middleware\CheckForAnyAbility;

->withMiddleware(function (Middleware $middleware) {
    $middleware->alias([
        'abilities' => CheckAbilities::class,     // TODAS las habilidades
        'ability'   => CheckForAnyAbility::class, // AL MENOS UNA habilidad
    ]);
})
// Token debe tener TODAS las habilidades enumeradas
Route::get('/orders', function () {
    // ...
})->middleware(['auth:sanctum', 'abilities:crear-articulo,editar-articulo']);

// Token debe tener AL MENOS UNA habilidad
Route::get('/orders', function () {
    // ...
})->middleware(['auth:sanctum', 'ability:crear-articulo,editar-articulo']);
